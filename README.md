# DSH Model Roles · 规划／执行模型

为 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) Web GUI 提供模型预设：一个**规划模型**，以及数量可自定义的**执行模型**。点击菜单或按快捷键，即可切换当前对话使用的模型。

输入框只增加一个 **模型预设** 按钮，不并排放置多个控件。

## 功能

- 规划模型固定一个；执行模型可逐项添加、删除，数量不限。
- 每个预设分别保存模型与可选的推理强度；模型与推理强度在同一行显示，不预设供应商或模型名称。
- 单按钮菜单提供「规划模型」「执行模型 N」「配置模型预设…」，角色行显示当前有效快捷键。
- 按钮在当前选择匹配预设时显示该预设名称；否则显示「模型预设」。若多个预设内容完全相同，按顺序取第一个。
- 删除执行模型后，其余执行模型按顺序重新编号，已配置的模型和推理强度保留。
- 复用 DSH 模型目录和选择接口，原有模型选择器与 `/model` 仍可正常使用。
- 失效模型、失效推理强度、配置冲突与切换失败会提示，不自动改选其他模型。

**只切换模型和推理强度，不切换规划模式或文件权限，不发送聊天消息，不自动规划或执行任务。**

## 安装

前提：已安装并配置 DSH，Web GUI 能正常列出至少一个可用模型。

### 用包名安装（npm）

在侧边栏 **插件 → 添加插件** 输入：

```text
dsh-model-roles
```

也可通过终端安装到 `web` profile：

```bash
dsh plugin --profile web add dsh-model-roles
```

### 从 GitHub 安装

在侧边栏 **插件 → 添加插件** 输入：

```text
https://github.com/qinpegnsen/dsh-model-roles.git
```

安装完成后启用插件。终端安装：

```bash
dsh plugin --profile web add https://github.com/qinpegnsen/dsh-model-roles.git
```

若使用其他 profile，请替换 `web`。仓库与 npm 包均包含构建产物，普通安装无需先构建，也无需另开 Web 服务器。

安装并启用后刷新 GUI，再打开一个普通对话，在输入框工具栏「权限」控件旁寻找 **模型预设** 按钮。若看不到，先在插件页核对启用状态，再刷新页面。

### 从源码本地安装

```bash
git clone https://github.com/qinpegnsen/dsh-model-roles.git
cd dsh-model-roles
npm run build
npm test
dsh plugin --profile web add "$PWD"
```

PowerShell 下最后一行可用：

```powershell
dsh plugin --profile web add (Get-Location).Path
```

构建和单元测试使用 Node.js 自带模块，不需要运行 `npm install`。React、UI 组件和模型服务由 DSH 在运行时提供。

## 使用

1. 点击输入框中的 **模型预设 → 配置模型预设…**。
2. 设置规划模型；需要多个执行模型时点 **添加执行模型**，不需要的点 **删除**。如果该模型提供推理强度，可在同一行选择，然后点击 **保存**。未保存时点 **取消** 不会修改现有配置。
3. 点击 **模型预设 → 规划模型 / 执行模型 N**，或使用快捷键切换。
4. 以 DSH 原有模型选择器显示的模型名称为准。切换从下一次模型请求开始生效，已经运行中的步骤不改变。

未配置预设时只提示先配置，不替你选择模型。要清除某一预设，在配置窗口选「未配置」后保存。

### 默认快捷键

| 预设 | Windows / Linux | macOS |
| --- | --- | --- |
| 规划模型 | `Ctrl + Alt + 1` | `⌘ + ⌥ + 1` |
| 执行模型 1 … 8 | `Ctrl + Alt + 2` … `Ctrl + Alt + 9` | `⌘ + ⌥ + 2` … `⌘ + ⌥ + 9` |
| 执行模型 9 | `Ctrl + Alt + 0` | `⌘ + ⌥ + 0` |
| 执行模型 10 及以后 | 默认不绑定 | 默认不绑定 |

Linux 的默认键位声明同 Windows；实际拦截由浏览器与桌面环境决定。在 **设置 → 编辑快捷键** 搜索「规划模型」或「执行模型」，可修改或清除绑定；已自定义的绑定优先于默认值。

Web 中快捷键面向当前主对话，不在终端、非对话面板或模态窗口中切换模型。DSH Desktop 的键盘拦截策略由宿主控制；本版本未进行 Desktop 实机验证。

## 配置与隐私

预设只保存在当前浏览器、当前 DSH 地址的 `localStorage`：

```text
dsh.model-roles.v1
```

只包含提供方 ID、模型 ID、可选的推理强度，以及执行模型的排列顺序；不保存密码、API Key、账号登录态或聊天内容。配置不会跨设备同步。不同标签页读取同一份配置；保存前会检查配置是否已被其他窗口修改。

0.1.x 写入的两模型配置会在读取时自动迁移，原有规划和执行模型保留，不额外添加执行模型。自 0.2.0 起新保存的数据使用版本 2 格式。

插件本身不新增网络请求或遥测。模型目录读取和模型切换由已有的 DSH 服务完成。

## 兼容性与验证范围

- 当前已核验的 DSH 版本：**0.2.0-rc.2**。
- 依赖 DSH 的 `modelDirectories`、`shortcuts`、`slots`、会话服务及共享 UI 组件；其他 DSH 版本尚未验证。
- **macOS Chrome Web GUI** 已实测 0.1.0：菜单配置与保存、菜单切换、快捷键、原生模型位回显、取消不写入、刷新后配置保留。
- 0.2.0 的可增删执行模型与同行推理强度在 Windows Web GUI 中实测过配置窗口、增删、保存与切换；macOS 未重新实测。
- Windows 默认键位已声明并在 Windows Web GUI 中实测；Linux 使用菜单或自行绑定。
- 不支持已寻址的子智能体会话。权限、模型凭据与供应商可用性仍由 DSH 管理。
- 当前单元测试覆盖配置校验与迁移、执行模型增删与重编号、动态快捷键注册清理、跨窗口冲突、切换互斥、无效模型拒绝、远程失败、会话生命周期，以及配置窗口与菜单的渲染契约。单元测试不替代实机 UI 验收。

## 开发

```bash
npm run build
npm test
```

- `src/core.cjs`：预设存储与迁移、执行模型增删、模型校验、切换、动态快捷键。
- `src/client.cjs`：单按钮菜单、配置窗口和反馈。
- `scripts/build.mjs`：生成 DSH 客户端 factory 与无行为的宿主入口。
- `lib/`：随仓库提供的构建产物，便于直接安装。改源码后先重新构建，再一并提交产物。
- `test/*.test.cjs`：不依赖账号、网络或浏览器的单元测试。

已安装插件的源码编辑不保证自动生效。没有对应构建监听时，重建后需停用并重新启用插件，再刷新 GUI；必要时按宿主提示重启 DSH。不要为此另开替代 GUI 服务器。

## 停用

在 **插件 → 规划／执行模型** 停用组合包，即移除单按钮菜单及快捷键。原有模型选择器继续可用；当前对话模型不随停用自动恢复。浏览器里的预设与快捷键覆盖保留，重新启用后可继续使用。
